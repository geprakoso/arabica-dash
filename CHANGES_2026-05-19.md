## Latar Belakang

Penjualan dan Tukar Tambah sudah memiliki state machine (`status_dokumen`: draft → final → locked, dengan void 1x). Namun **Pembelian** masih menggunakan `is_locked` (boolean) tanpa `status_dokumen`, sehingga:

- Tidak ada alur draft → final yang jelas
- Tidak ada void (pembatalan)
- Tidak ada audit trail (siapa, kapan post/void)
- Tidak konsisten dengan Penjualan & Tukar Tambah

---

## Masalah Awal

| Aspek | Sebelum | Penjualan (referensi) |
|---|---|---|
| Field status | `is_locked` (boolean) | `status_dokumen` (enum) |
| Alur | Draft → Lock (langsung) | Draft → Final → Locked |
| Void | ❌ Tidak ada | ✅ 1x |
| Audit trail | ❌ Tidak ada | ✅ posted_at, voided_at, dll |

## Evolusi Perubahan

### Iterasi 1: Tambah State Machine Lengkap (draft/final/locked/voided)

Meniru persis Penjualan & Tukar Tambah:
- Tambah `status_dokumen` enum: draft, final, locked, voided
- Tambah field: `void_used`, `posted_at`, `posted_by_id`, `voided_at`, `voided_by_id`
- Flow: `draft → post() → final → lockFinal() → locked`, `final → voidToDraft() → draft`

**Masalah:** Data lama `is_locked=true` dimigrasi ke `locked`, tapi `canVoid()` hanya izinkan void dari `final`. Data lama tidak bisa di-void.

### Iterasi 2: Expand canVoid() untuk Locked

`canVoid()` diubah dari `isFinal() && !is_locked` menjadi `isFinal() || isLocked()`. Data lama locked bisa di-void 1x.

**Masalah:** Setelah void, `is_locked` tidak di-reset ke `false`, sehingga `canPost()` dan `canEditPayment()` gagal. Fixed dengan menambahkan `'is_locked' => false` di `voidToDraft()`.

**Pertanyaan muncul:** Kalau locked bisa di-void, apa bedanya dengan final? Perbedaan hanya "final bisa di-lock, locked tidak". Tujuan awal locked sebagai "point of no return" hilang.

### Iterasi 3: Hapus Status Locked

Keputusan: **Pembelian tidak butuh locked** karena:
- Item memang tidak bisa diedit (selalu `canEditItems() = false`)
- Final bisa di-void 1x, jadi tidak butuh penguncian lebih lanjut
- Locked yang bisa void = tidak ada gunanya

Perubahan:
- Hapus `isLocked()`, `canLock()`, `lockFinal()` dari model
- Hapus `locked` dari enum `status_dokumen`
- Flow disederhanakan: **draft → final**, **final → draft (void 1x)**
- Data lama `locked` dimigrasi ke `final`

**Masalah:** Data lama `is_locked=true` setelah jadi `final` tetap tidak bisa di-void (karena `canVoid()` cek `!is_locked`). Fixed dengan migration unlock data lama (kecuali yang terikat TT).

### Iterasi 4: Pembelian dari Tukar Tambah

Pembelian yang terikat TT seharusnya **tidak bisa di-post/void/edit secara independen** — semua kontrol lewat TT. Ditambahkan `isFromTukarTambah()` check di `canPost()`, `canVoid()`, `canEditPayment()`.

## Error yang Ditemukan & Penyelesaiannya

### Error 1: `sale_tt` tidak ada di enum `stock_mutations.type`

```
SQLSTATE[01000]: Warning: 1265 Data truncated for column 'type' at row 1
SQL: insert into `stock_mutations` (...) values (..., sale_tt, ...)
```

**Penyebab:** Kode `PenjualanItem.php` sudah menggunakan `sale_tt` untuk stock mutation dari Tukar Tambah, tapi enum database belum menyertakan nilai tersebut.

**Solusi:** Migration menambahkan `sale_tt` ke enum:
```sql
ALTER TABLE stock_mutations MODIFY COLUMN type 
ENUM('purchase','sale','sale_tt','opname','adjustment','rma_return','initial_sync','sale_return')
```

### Error 2: `sale_return_tt` juga belum ada di enum

**Penyebab:** Sama seperti di atas, `PenjualanItem.php:75` menggunakan `sale_return_tt` untuk return dari TT, tapi enum belum ada.

**Solusi:** Migration menambahkan `sale_return_tt` ke enum.

### Error 3: Data lama `is_locked=true` tidak bisa di-void setelah migrasi ke `final`

**Penyebab:** `canVoid()` mengecek `!is_locked`, tapi data lama dari TT tetap punya `is_locked=true`.

**Solusi:** Migration unlock data lama yang `final + is_locked=true + tanpa TT`, kecuali yang terikat Tukar Tambah.

### Error 4: Pembelian TT-202605-001 ke-unlock padahal terikat TT

**Penyebab:** Migration unlock hanya filter `no_tt`, tidak cek relasi `tukarTambah`.

**Solusi:** Update migration untuk exclude pembelian yang punya relasi Tukar Tambah (`whereNotIn('id_pembelian', $ttPembelianIds)`).

## Behavior Baru — State Machine Pembelian

### Diagram Alur

```
┌─────────┐   post()   ┌─────────┐  voidToDraft()  ┌─────────┐
│  DRAFT  │ ──────────► │  FINAL  │ ──────────────► │  DRAFT  │
│         │             │         │   (1x saja)     │         │
└─────────┘             └─────────┘                  └─────────┘
     ▲                       │
     │                       │ (dari TT)
     │                       ▼
     │                 is_locked=true
     │                 (tidak bisa void independen)
     │
     └── canEditPayment=true
         canPost=true
```

### Aturan State

| Status | canPost | canVoid | canEditPayment | canEditItems |
|---|---|---|---|---|
| **Draft** (biasa) | ✅ | ❌ | ✅ | ❌ |
| **Draft** (dari TT) | ❌ | ❌ | ❌ | ❌ |
| **Final** (biasa, belum void) | ❌ | ✅ | ❌ | ❌ |
| **Final** (dari TT) | ❌ | ❌ | ❌ | ❌ |
| **Final** (sudah void) | ❌ | ❌ | ❌ | ❌ |

### Perbandingan dengan Penjualan

| Aspek | Pembelian | Penjualan |
|---|---|---|
| Status | draft, final | draft, final, locked |
| Locked | ❌ Tidak ada | ✅ Ada |
| Void | final → draft (1x) | final → draft (1x) |
| Edit item | ❌ Selalu tidak bisa | ✅ Draft bisa |
| Edit pembayaran | ✅ Draft bisa | ✅ Draft bisa |
| TT-linked | Tidak bisa post/void independen | Kontrol via TT |

### `isFromTukarTambah()` Guard

Pembelian yang terikat Tukar Tambah (`$pembelian->tukarTambah()->exists() === true`) tidak memiliki aksi independen:
- **Tidak bisa post** — status diatur oleh TT `post()`
- **Tidak bisa void** — status diatur oleh TT `voidToDraft()`
- **Tidak bisa edit pembayaran** — diatur oleh TT

### Cascade dari Tukar Tambah

| Aksi TT | Pembelian |
|---|---|
| TT `post()` | `status_dokumen='final'`, `is_locked=true` |
| TT `voidToDraft()` | `status_dokumen='draft'`, `is_locked=false`, `void_used=true` |
| TT `lockFinal()` | `status_dokumen='final'`, `is_locked=true` |

### Tampilan List

- **Status badge** — Sama seperti Penjualan: DRAFT (gray), FINAL (success), LOCKED (danger untuk is_locked=true), VOIDED (warning)
- **Tab filter** — 3 tab: Semua, Draft, Final (termasuk locked/is_locked)
- **Actions** — Posting (draft→final), Void (final→draft 1x)
- **Icon** — Sama seperti Penjualan: `receipt-percent`, `arrow-uturn-left`, dll

### Stock Mutation Type Baru

| Type | Kegunaan |
|---|---|
| `sale_tt` | Stok keluar dari penjualan Tukar Tambah |
| `sale_return_tt` | Return stok dari penjualan Tukar Tambah |
